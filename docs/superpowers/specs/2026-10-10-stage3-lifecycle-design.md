# Этап 3 — жизненный цикл Windows: дизайн

**Дата:** 2026-10-10
**Статус:** согласовано в обсуждении, ожидает просмотра спецификации
**Основа:** спецификации Этапов 1–2, итоги ручной проверки Этапа 2 (`docs/testing.md`)

## 1. Цель и границы

Лента ведёт себя вместе с компьютером: гаснет, когда пользователя нет за экраном
или компьютер выключается, и сама возвращается в выбранный режим; приложение
запускается вместе с Windows.

**Входит:**

- выключение, перезагрузка, выход из сеанса — лента гаснет;
- сон — лента гаснет, после пробуждения режим восстанавливается;
- блокировка экрана — лента гаснет, после разблокировки режим восстанавливается;
- отключение дисплея по таймеру Windows — лента гаснет, при включении дисплея
  режим восстанавливается;
- автозапуск через `HKCU\…\Run`, флажок в «Общих», включён по умолчанию.

**Не входит:** глобальная горячая клавиша; отслеживание выключения монитора его
собственной кнопкой (Windows об этом не сообщает); чтение состояния
«Автозагрузки» Диспетчера задач (`StartupApproved`).

### 1.1. Исходные данные (проверка Этапа 2)

- После аварийного завершения в direct mode лента бесконечно держит последний
  кадр Ambilight; Apple Home ей управляет (A13). Автозапуск закрывает этот случай
  после перезагрузки.
- Экран блокировки рисуется на рабочем столе пользователя, захват его видит (A8).
  Теперь при блокировке лента гаснет.

## 2. Модель: причины тьмы

- `enum Dark { Sleep, Locked, DisplayOff }`; контроллер хранит набор причин
  (`BTreeSet<Dark>`).
- Команды `Darken { reason }` и `Undarken { reason }`; повтор той же команды ничего
  не меняет.
- `desired()`: пока набор не пуст — «выключена» (`Light(off)`), иначе — как в
  Этапе 2 (Статика / Ambilight / Выкл по конфигу).
- **Конфиг от событий Windows не меняется:** питание, режим, цвет пользователя
  сохраняются; `config.toml` не перезаписывается.
- Переходы — через существующий `drive()`:
  - первая причина в Ambilight → `StopStream { then: off }`;
  - первая причина в Статике → `Apply(off)`;
  - уход последней причины → `drive(desired())` (Ambilight снова стримит,
    Статика применяет цвет, Выкл — ничего не шлёт, кроме `off`).
- Изменения пользователя во время тьмы (цвет, режим, питание) сохраняются в конфиг,
  но к ленте не уходят — применяются при снятии последней причины.
- Офлайн: в `pending` остаётся состояние «с учётом тьмы»; после переподключения
  действует текущий набор причин.
- Подсветка редактора во время тьмы отклоняется с ошибкой; активная подсветка при
  появлении причины прекращается.
- `EndSession` — как `Exit`, но лента гаснет всегда, независимо от
  `exit_action`: при стриме — `stop_stream` с `then = off`, иначе — `power_off`.
  Короткие таймауты, как у выхода.
- В `Snapshot` — список текущих причин; иконка в тьме — «выключено» (серое
  кольцо), подсказка «Выключено · экран заблокирован / сон / экран выключен»;
  в «Диагностике» строка «Пауза: …».

## 3. События Windows в трее

### 3.1. Подписки

Выполняются при создании скрытого окна; неудача — предупреждение в лог, работа
продолжается.

| Источник | Событие | Команда |
|---|---|---|
| `WTSRegisterSessionNotification(hwnd, NOTIFY_FOR_THIS_SESSION)` → `WM_WTSSESSION_CHANGE` | `WTS_SESSION_LOCK` | `Darken(Locked)` |
| | `WTS_SESSION_UNLOCK` | `Undarken(Locked)` |
| `RegisterPowerSettingNotification(hwnd, GUID_CONSOLE_DISPLAY_STATE, DEVICE_NOTIFY_WINDOW_HANDLE)` → `WM_POWERBROADCAST` / `PBT_POWERSETTINGCHANGE` | данные 0 (выкл.) | `Darken(DisplayOff)` |
| | 1 (вкл.), 2 (приглушён) | `Undarken(DisplayOff)` |
| `WM_POWERBROADCAST` | `PBT_APMSUSPEND` | `Darken(Sleep)` с ожиданием 1,5 с |
| | `PBT_APMRESUMEAUTOMATIC`, `PBT_APMRESUMESUSPEND` | `Undarken(Sleep)` |
| `WM_QUERYENDSESSION` | — | ответ TRUE, без задержки |
| `WM_ENDSESSION`, wParam = TRUE | — | `EndSession` с ожиданием 2 с, затем удалить иконку и завершиться |

- Перевод сообщений в события — чистая функция
  `ui::lifecycle::event(msg, wparam, display_state) -> Option<LifecycleEvent>`.
- Отписки (`WTSUnRegisterSessionNotification`, `UnregisterPowerSettingNotification`)
  — при уничтожении окна.

### 3.2. Ожидание обработки

- `WorkerHandle::send_and_wait(cmd, timeout) -> bool`: номер команды берётся из
  счётчика отправленных; worker после каждой пачки команд публикует число
  обработанных (`Mutex<u64>` + `Condvar`); отправитель ждёт, пока оно дойдёт до его
  номера. Таймаут — продолжаем без ожидания (Windows ждать не будет).
- Таймауты: сон 1,5 с, завершение сеанса 2 с.

### 3.3. Защита от потерянных событий

- Любое пробуждение и разблокировка снимают `Sleep`.
- Включение дисплея снимает `DisplayOff`.
- Сразу после пробуждения сети может не быть: первая попытка уйдёт в Offline,
  дальше — обычные повторы Этапа 1.

## 4. Автозапуск

- Значение `ObsidAmbilight` в `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`,
  данные — полный путь к exe в кавычках.
- Конфиг: `[startup] autostart = true`; отсутствие ключа → `true` (при первом
  запуске новой версии приложение прописывает себя само).
- Синхронизация при каждом старте фонового процесса: `autostart = true` и значения
  нет или путь другой → записать текущий путь; `false` и значение есть → удалить.
  Ошибка реестра → «Диагностика», запуск продолжается.
- Флажок «Запускать вместе с Windows» в «Общих» → `SetAutostart { enabled }` →
  контроллер сохраняет конфиг и выдаёт `SyncAutostart`; выполняет worker.
  В реестр пишет только фоновый процесс.
- Подсказка у флажка: «Можно также отключить в Диспетчере задач → Автозагрузка».
  Отключение там Windows хранит отдельно (`StartupApproved`); приложение его не
  читает и не перезаписывает.
- Модуль `platform::autostart`: `read(key, name) -> io::Result<Option<String>>`,
  `write(key, name, value)`, `remove(key, name)`; путь к ключу — параметр.
- Новые функции `windows-sys`: `Win32_System_Registry`, `Win32_System_Power`
  (`Win32_System_RemoteDesktop` уже подключена).

## 6. Тестирование

Автоматические:

- `controller_tests` — блокировка/разблокировка в Статике и Ambilight; две причины
  (блокировка + экран выключен) — восстановление после снятия обеих; изменения во
  время тьмы применяются после неё и сохраняются в конфиг; тьма в офлайне →
  после переподключения лента гаснет; `EndSession` гасит при любом `exit_action`;
  подсветка во время тьмы отклоняется; конфиг не меняется от событий;
  `SetAutostart` → `SyncAutostart`.
- `worker_tests` — `send_and_wait` возвращает `true` после обработки и `false` по
  таймауту; блокировка в Ambilight останавливает захват и стрим, разблокировка
  запускает их снова.
- `lifecycle_tests` — перевод сообщений: LOCK, UNLOCK, SUSPEND, RESUME*, дисплей
  0/1/2, ENDSESSION TRUE/FALSE, посторонние → `None`.
- `autostart_tests` — запись, чтение, смена пути, удаление в
  `HKCU\Software\ObsidAmbilightTest\Run`; ключ удаляется после теста.
- `config_tests` — конфиг без `autostart` → `true`; круговое сохранение.

Каждая задача: `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`,
`cargo test`.

Ручные (раздел Этапа 3 в `docs/testing.md`): Win+L и разблокировка в Статике и
Ambilight; отключение экрана по таймеру; сон и пробуждение; перезагрузка (лента
погасла → после входа приложение запустилось само и включило режим); выход из
сеанса; флажок автозапуска вкл/выкл с проверкой в «Автозагрузке» Диспетчера
задач; Apple Home после каждого сценария.

## 7. Критерии готовности Этапа 3

- При блокировке, сне, отключении экрана, перезагрузке и выходе из сеанса лента
  гаснет; при разблокировке, пробуждении и включении экрана режим
  восстанавливается сам.
- После перезагрузки приложение запускается само и включает последний режим;
  застывших кадров Ambilight не остаётся.
- Выбор пользователя (питание, режим, цвет) из-за событий Windows не меняется.
- Все автотесты, `fmt` и `clippy` зелёные; ручной чек-лист пройден.

## 8. Риски

- Windows даёт мало времени при сне и завершении сеанса: лента может не успеть
  погаснуть при медленной сети (ожидание ограничено 1,5–2 с).
- Пробуждение без сети: первая попытка уходит в Offline, восстановление — по
  обычному расписанию повторов.
- Если пользователь отключил приложение в «Автозагрузке» Диспетчера задач, флажок
  в «Общих» продолжит показывать «включено» — это объяснено подсказкой.
