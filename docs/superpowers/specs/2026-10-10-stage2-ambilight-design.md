# Этап 2 — Ambilight: дизайн

**Дата:** 2026-10-10
**Статус:** согласовано в обсуждении, ожидает просмотра спецификации
**Основа:** итоги Этапов 0–1 (`docs/protocol.md`, спецификация Этапа 1), требования
собраны в обсуждении (исходное ТЗ v1.0 недоступно)

## 1. Цель и границы

Режим Ambilight: цвета краёв выбранного монитора в реальном времени передаются на
ленту Yeelight Obsid (Chameleon2) через direct mode (`update_leds`). Сценарии —
игры (включая полноэкранные), видео и фильмы, SDR и HDR.

**Входит в Этап 2:**

- третий режим ленты — Ambilight — рядом с «Выкл» и «Статикой», в трее и в окне;
- захват экрана DXGI Desktop Duplication на адаптере выбранного монитора,
  уменьшение кадра на GPU, автоматическое определение HDR и перевод в SDR;
- произвольная раскладка ленты из сегментов-отрезков на схеме экрана;
- визуальный редактор раскладки с подсветкой диодов и сегментов на ленте;
- обработка цвета: чёрные полосы, насыщенность, яркость, порог черноты, сглаживание;
- сохранение режима и автоматическое возобновление Ambilight после перезапуска
  приложения и после восстановления связи;
- выход из приложения и смена режима с корректным выходом из direct mode;
- диагностика захвата и стрима, строки RU/EN.

**Не входит:** автозапуск, сон, блокировка и завершение сеанса Windows (Этап 3);
автоматическое включение Ambilight по полноэкранному приложению; захват через GDI
как запасной вариант; цветокоррекция ленты (баланс белого); глобальная горячая
клавиша.

### 1.1. Исходные данные

- Лента уложена на задней крышке основного монитора спиралью из двух витков:
  внешний виток по периметру (низ разорван подставкой), внутренний — меньший
  прямоугольник с диагональным участком. Оба витка показывают края экрана;
  внутренний — вторым слоем. По фото около 60 диодов; точное число и индекс 0
  проверяются шаблонами `ends`/`chase`.
- Мониторы: основной 2560×1440 @ 240 Гц на GeForce GTX 1050 Ti, второй
  1920×1080 на Intel UHD 730. Лента — на основном.
- HDR может быть включён или выключен; поддерживаются оба режима.

## 2. Ограничения из Этапов 0–1

- `update_leds` без ответа (fire-and-forget); подтверждено 20 FPS для 60 диодов.
- `activate_fx_mode direct` / `deactivate_fx_mode direct` подтверждены; после
  `deactivate_fx_mode` статический цвет сохраняется.
- Потеря сессии обнаруживается только по keep-alive (3 пропуска подряд).
- Перемежающиеся отказы Apple Home, причина не установлена: LAN-трафик к ленте
  минимизируется (отправка кадров только при изменениях).
- Один поток (worker) владеет связью с лентой; `Controller` — чистая машина
  состояний без сети, потоков и часов.

## 3. Модель раскладки

### 3.1. Сегменты

Сегмент — диапазон диодов, равномерно разложенный по отрезку на экране.

```toml
[[ambilight.segments]]
from = 0                # первый диод (включительно)
to = 11                 # последний диод (включительно); from > to — обратный порядок
start = [0.10, 0.50]    # точка экрана (x, y) в долях 0..1, вид спереди
end   = [0.20, 0.05]
```

- Диод `i` сегмента из `n` диодов стоит в точке `start + (end − start) · t`, где
  `t = (k + 0.5) / n`, `k` — порядковый номер диода внутри сегмента
  (0 — диод `from`). При `n = 1` диод стоит в середине отрезка.
- Цвет диода — средний цвет квадрата со стороной `depth × min(W, H)` с центром в
  его точке; квадрат сдвигается внутрь кадра, если выходит за край.
- Сегменты могут пересекаться на экране, но не по диодам.
- Диоды, не входящие ни в один сегмент, не горят (чёрный).
- Ограничения: сегментов ≤ 16; `from`, `to` < `led_count`; координаты в [0, 1].

### 3.2. Проверка

- Загрузчик: сегмент с координатами вне [0, 1], индексами вне `led_count` или
  диодами, уже занятыми предыдущим сегментом, отбрасывается с предупреждением
  (как плохие поля в Этапе 1). Сегменты сверх 16 отбрасываются.
- Редактор показывает ту же ошибку у сегмента и не отправляет неверную раскладку.
- При уменьшении `led_count` сегменты, выходящие за новое число диодов,
  обрезаются; пустые удаляются.

### 3.3. Шаблон «периметр»

Генерирует 4 сегмента по часовой стрелке (вид спереди) от левого нижнего угла:
левая сторона снизу вверх, верх слева направо, правая сверху вниз, низ справа
налево. Вход — число диодов на каждой стороне, сумма ≤ `led_count`. Отрезки
проходят по линии 0.02 от края экрана. Раскладка по умолчанию — периметр,
разложенный по `led_count` пропорционально сторонам 16:9.

## 4. Захват

### 4.1. Desktop Duplication

- По `ambilight.monitor` (`DeviceName`, например `\\.\DISPLAY1`; пусто —
  основной) найти адаптер и выход DXGI; создать D3D11-устройство на этом адаптере.
- `IDXGIOutput5::DuplicateOutput1` с форматами
  `[DXGI_FORMAT_R16G16B16A16_FLOAT, DXGI_FORMAT_B8G8R8A8_UNORM]`: на HDR-выходе
  кадры приходят в FP16 scRGB, на SDR — в BGRA8. Формат кадра определяет режим HDR.
- Кадр копируется в нулевой уровень текстуры с mip-уровнями
  (`D3D11_RESOURCE_MISC_GENERATE_MIPS`), затем `GenerateMips`. Читается уровень, ширина
  которого первой окажется ≤ 256 (для 2560×1440 — 160×90): копия в staging-текстуру,
  `Map`, перевод в маленький кадр `f32 RGB`.
- `AcquireNextFrame` с таймаутом ≈ 1/fps. Нет нового кадра — остаётся предыдущий
  маленький кадр, конвейер продолжает работу (сглаживание доходит до цели).
- Уровень белого SDR — `DisplayConfigGetDeviceInfo`
  (`DISPLAYCONFIG_DEVICE_INFO_GET_SDR_WHITE_LEVEL`), перечитывается при каждом
  пересоздании захвата.

### 4.2. Ошибки захвата

- `DXGI_ERROR_ACCESS_LOST` (смена режима, HDR вкл/выкл, переключение полного
  экрана), `E_ACCESSDENIED` / `DXGI_ERROR_ACCESS_DENIED` (UAC, экран блокировки),
  отключённый монитор → захват закрывается и пересоздаётся раз в 1 с. До
  восстановления слот не обновляется, лента держит последние цвета.
- Монитор `ambilight.monitor` не найден → основной, предупреждение в «Диагностике».
- Ошибка захвата не меняет режим и не считается потерей связи с лентой.

### 4.3. Поток захвата

- Запускается worker'ом при начале стрима и останавливается при его окончании
  (флаг остановки + join). Вне стрима GPU и CPU не используются.
- Владеет D3D11-устройством и конвейером цвета. Результат — массив цветов
  диодов длиной `led_count` — кладётся в общий слот «последний кадр»
  (`Arc<Mutex<Option<LedFrame>>>`, новый кадр затирает старый).
- Настройки и раскладка передаются потоку через общую ячейку
  (`Arc<Mutex<AmbilightConfig>>`), которую worker обновляет при изменениях;
  поток читает её раз за итерацию.
- Статистика (FPS захвата, HDR, уровень белого, полосы, последняя ошибка,
  имя монитора и адаптера) публикуется в общую структуру и попадает в `Snapshot`.

## 5. Цветовой конвейер

Чистые функции над маленьким кадром; без Win32, покрываются тестами.

1. **HDR → SDR.** FP16 scRGB линейный, 1.0 = 80 нит. Значения делятся на
   `sdr_white_nits / 80`, так что белый SDR становится 1.0; отрицательные
   компоненты (широкий охват) обрезаются до 0. Света выше белого SDR сжимаются с
   сохранением оттенка: если максимальный канал > 1, все три канала делятся на
   него. Затем линейные значения кодируются в sRGB. Белый SDR → 255, яркие
   источники — насыщенный цвет, а не белый. SDR-кадр (BGRA8) уже в sRGB и
   проходит как есть.
2. **Чёрные полосы** (флаг `letterbox`, по умолчанию вкл). Ряд или столбец
   считается чёрным, если максимум каналов всех его пикселей < 0.06 (sRGB).
   Полосы ищутся парами сверху/снизу и слева/справа, ширина пары — по меньшей из
   двух сторон; полосы шире 30 % стороны не принимаются. Новая граница
   применяется, только если держится 1 с (гистерезис); полностью чёрный кадр
   границ не меняет. Точки раскладки пересчитываются в область внутри полос.
3. **Выборка.** Средний цвет квадрата вокруг точки каждого диода (раздел 3.1).
4. **Коррекция.** Насыщенность (×0.5–2.0, по умолчанию 1.2) — смешение с
   яркостью Rec.709; порог черноты (0–20 %, по умолчанию 3 %) — диоды с максимумом
   каналов ниже порога гаснут; яркость Ambilight (1–100 %, по умолчанию 100) —
   умножение.
5. **Сглаживание.** Экспоненциальное: `c += (target − c) · (1 − e^(−dt/τ))`,
   `τ` = «Плавность» 0–100 % → 0–500 мс (по умолчанию 25 % ≈ 125 мс). Смена сцены —
   средняя яркость всех диодов изменилась более чем на 0.25 за кадр — сглаживание
   на этот кадр отключается.
6. Перевод в байты `Rgb` с округлением.

## 6. Режимы, состояния и протокол

### 6.1. Конфигурация

```toml
[app]
mode = "static"          # "static" | "ambilight"; общий вкл/выкл — static.power

[ambilight]
monitor = ""             # DeviceName; пусто — основной
fps = 25                 # 10–30
depth = 0.08             # 0.02–0.25
brightness = 100         # 1–100
saturation = 1.2         # 0.5–2.0
smoothing = 25           # 0–100
black_threshold = 3      # 0–20
letterbox = true

[[ambilight.segments]]   # раздел 3
```

- Выкл / Статика / Ambilight = `power = off` / `on + static` / `on + ambilight`.
- Конфиг Этапа 1 читается без изменений: `mode = static`, Ambilight по умолчанию.
- Невалидное поле — сброс поля с предупреждением; невалидный сегмент — по 3.2.

### 6.2. Controller

- `LightChange` заменяется желаемым состоянием ленты
  `Desired = Off | Static { color, brightness } | Ambilight`; `pending` хранит его
  же, поэтому после разрыва связи возобновляется последний режим.
- Controller знает, идёт ли стрим (`streaming: bool`).
- Действия: `Apply { ip, desired }` для Off/Static (вне стрима),
  `StartStream { ip }`, `StopStream { ip, then: Off | Static }`.
  Переход Static → Ambilight — `StartStream`; Ambilight → Static/Off —
  `StopStream` с соответствующим `then`; изменение цвета в Статике — `Apply`.
- События: `StreamStarted(Result<(), String>)`, `StreamStopped(Result<(), String>)`,
  `StreamFailed(String)`. Ошибка старта или сбой стрима → Offline, `pending =
  Ambilight`, повторы с той же задержкой; после `Resolved` — снова `StartStream`.
- Команды: `SetMode { mode }`, `SetAmbilight { settings }` (всё из 6.1 кроме
  сегментов), `SetLayout { segments }`, `Highlight { target }`,
  `StopHighlight`. `SetStatic` и выбор пресета переводят в режим Статика.
  `SetLedCount` обрезает сегменты (3.2).
- **Подсветка** (`Highlight`): цель — `Led(i)` или `Segment(k)`. Если стрима нет,
  controller запускает его (`StartStream`) только для подсветки; worker
  показывает кадр подсветки вместо захваченного. Подсветка истекает через 3 с
  без повторного `Highlight` (дедлайн controller'а) или по `StopHighlight`; затем
  лента возвращается в режим пользователя (стрим продолжается для Ambilight или
  останавливается с `then` = Static/Off). Во время подсветки поток захвата не нужен
  и не запускается (в режиме Ambilight он продолжает работать, но его кадры не
  отправляются). Подсветка вне состояния Ready (Offline, NoDevice) отклоняется с
  ошибкой в «Диагностике».
- Выход (`Exit`): при активном стриме — `Shutdown { stop_stream: Some(then) }`, где
  `then = Static` для `exit_action = keep` (живой стрим без приложения не
  удержать) и `Off` для `exit_action = off`; вне стрима — как в Этапе 1.

### 6.3. Worker и link

`DeviceLink` получает методы:

- `start_stream(ip, led_count)` — новая сессия → `set_power on` →
  `set_bright 100` → `activate_fx_mode direct`. Яркость Ambilight применяется в
  ПО, аппаратная фиксируется на 100.
- `send_frame(&[Rgb])` — `update_leds` без ответа.
- `stream_tick(now)` — keep-alive по `Chameleon2::tick` (раз в 3 с); ошибка,
  после которой сессия закрыта, → `StreamFailed`.
- `stop_stream(then)` — `deactivate_fx_mode direct` → для Static: цвет, яркость;
  для Off: `set_power off`. Для выхода — короткие таймауты (≤ ~1 с суммарно).

Цикл worker'а:

- При активном стриме в дедлайны добавляется время следующего кадра (1/fps).
- По дедлайну: подсветка активна → кадр подсветки; иначе последний кадр из слота.
  Кадр отправляется, если он отличается от последнего отправленного или с прошлой
  отправки прошла 1 с. Затем `stream_tick`.
- Поток захвата запускается после успешного `start_stream` в режиме Ambilight и
  останавливается перед `stop_stream`, при `StreamFailed` и при выходе.
- Пачки команд и схлопывание остаются; ограничение 5 применений/с — только для
  `Apply` статики. Подряд идущие `SetAmbilight`, `SetLayout`, `Highlight`
  схлопываются до последнего.
- Изменения `SetAmbilight`/`SetLayout` попадают в общую ячейку настроек потока
  захвата сразу, без перезапуска стрима; смена монитора пересоздаёт захват.

### 6.4. Аварийное завершение

Сессия истекает сама; поведение ленты после истечения direct-сессии без
`deactivate_fx_mode` не изучено (строка 11 чек-листа Этапа 0) и проверяется
вручную. Panic в потоке захвата ловится, записывается в ошибки и через 1 с
поток перезапускается (не более 3 раз подряд, затем ошибка в «Диагностике»,
режим не меняется).

## 7. Трей

- Меню: строка состояния → «Выключить/Включить» → радио-пункты **«Статика»** и
  **«Ambilight»** → «Цвет ▸» (выбор цвета переводит в Статику) → «Яркость ▸» (в
  режиме Ambilight меняет яркость Ambilight) → «Искать ленту снова» → «Настройки…»
  → «Выход».
- Иконка Ambilight — кольцо из 4 цветных дуг (рисуется кодом). Захват недоступен —
  маленькая жёлтая точка поверх кольца.
- Подсказка: `Obsid Ambilight — Ambilight · 25 FPS · HDR · 192.168.1.85`;
  при недоступном захвате — «захват недоступен».

## 8. Окно настроек

- Новая вкладка **«Ambilight»** между «Подсветкой» и «Общими».
- Стартовый размер окна ~900×600 (минимум прежний 560×400).
- Верх: «Включить Ambilight» (переключает режим), монитор (список выходов
  с разрешением; «Основной» — пустое значение), FPS 10–30.
- «Изображение»: яркость, насыщенность, плавность, порог черноты, «Убирать
  чёрные полосы», глубина выборки.
- «Раскладка»:
  - схема монитора с пропорциями выбранного экрана; сегменты — цветные отрезки
    со стрелкой направления и номерами крайних диодов; концы перетаскиваются
    мышью с привязкой к краям, углам и сетке 5 %;
  - список сегментов: «с», «по», координаты числами, «Добавить», «Удалить»,
    «Развернуть», ошибки проверки у сегмента;
  - «Шаблон: периметр» — число диодов на каждой стороне;
  - «Поиск диода»: слайдер №; на ленте горит выбранный диод белым, по 10 соседей
    с каждой стороны — тускло (видно направление);
  - «Показывать на ленте»: выбранный в списке сегмент горит, остальные погашены;
    пока флажок включён и вкладка открыта, окно повторяет `Highlight` раз в ~1 с.
- Изменения применяются сразу, без кнопки «Сохранить»; ползунки шлют команды не
  чаще ~5 раз в секунду (как цвет в Этапе 1), последнее значение — всегда.
- Мониторы окно перечисляет само (DXGI, дёшево); в конфиг пишется только `DeviceName`.
- «Диагностика» дополняется: режим, монитор и адаптер, HDR да/нет и уровень
  белого SDR, FPS захвата и отправки за последние 5 с, найденные полосы,
  последняя ошибка захвата.
- Все новые строки — в `Strings` RU/EN.

## 10. Тестирование

Автоматические (без железа и GPU):

- `layout_tests` — точки диодов, обратный порядок, `n = 1`, пересечения,
  границы, обрезка при смене `led_count`, шаблон периметра, круговое сохранение TOML;
- `color_tests` — HDR→SDR (белый SDR → 255, сжатие светов с сохранением оттенка,
  отрицательные значения), насыщенность, порог, яркость;
- `letterbox_tests` — 21:9, 4:3, тёмная сцена не даёт полос, гистерезис,
  чёрный кадр;
- `pipeline_tests` — синтетический кадр → цвета диодов; сглаживание и сброс
  на смене сцены;
- `controller_tests` — Статика ↔ Ambilight ↔ Выкл, `StreamFailed` → Offline →
  возобновление Ambilight, выход из Ambilight с keep/off, подсветка и её истечение,
  подсветка из Статики;
- `worker_tests` — фейковые link и источник кадров: отправка только изменений
  плюс раз в 1 с, keep-alive, сбой стрима, захват не запускается вне стрима;
- `config_tests` — конфиг Этапа 1 с `mode = static`, плохие поля и сегменты;
- `capture_tests` с `#[ignore]` — реальный захват основного монитора: кадр
  получен, размер ≤ 256 по ширине (`cargo test -- --ignored`).

Каждая задача: `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`,
`cargo test`.

Ручные (раздел Этапа 2 в `docs/testing.md`): шаблоны `ends`/`chase` (число диодов,
индекс 0); сборка раскладки спирали в редакторе; игра в полноэкранном режиме;
видео 21:9; HDR вкл/выкл во время работы; UAC и блокировка; 20/25/30 FPS; влияние
`set_bright` в direct mode; отключение питания ленты во время Ambilight →
возобновление; выход keep/off из Ambilight; принудительное завершение процесса во
время стрима; Apple Home после каждого сценария; замер CPU/RAM.

## 11. Критерии готовности Этапа 2

- Ambilight включается из трея и окна, сохраняется, сам возобновляется после
  перезапуска приложения и после восстановления связи.
- Раскладка из произвольных сегментов настраивается в редакторе с подсветкой на
  ленте; спираль из двух витков показывает края экрана обоими витками.
- Работают полноэкранные игры, видео и HDR (цвета не блёклые); чёрные полосы
  фильмов не попадают в выборку.
- Задержка экран → лента визуально незаметна при плавности по умолчанию.
- Фоновый процесс в Ambilight при 25 FPS на 1440p: ≤ 3 % CPU в среднем,
  ≤ 60 МБ RAM. В Статике — цели Этапа 1 (поток захвата не запущен).
- Все автоматические проверки зелёные.

## 12. Риски

- 30 FPS и Apple Home: по умолчанию 25 FPS, кадры отправляются только при изменениях.
- Влияние `set_bright` на direct mode не изучено: аппаратная яркость фиксируется
  на 100, проверка в чек-листе.
- Desktop Duplication может не работать в отдельных конфигурациях гибридной
  графики: ошибка в «Диагностике», запасного захвата нет.
- Объём unsafe/COM-кода: изолирован в `src/capture/`, остальной конвейер чистый.
